Shipment Manager v2

One shipment, one or many Odoo Purchase Orders. Physical receiving is compared with the correct PO, converted into each product's Odoo UOM (Allowed Uom), and exported as one reconciliation workbook per PO plus a master shipment workbook. Only validated / resolved rows reach an Odoo Upload File. Quantities are never combined across POs. v1 stays untouched in Shipment_Manager.html.

1 · Shipment & Purchase Orders

Load one Odoo export per PO (e.g. P00343.xlsx). The PO reference comes from the file name and can be corrected; the vendor is entered or chosen on import; Stock Moves/Reference (e.g. BFL/IN/00067) is kept as the receipt reference, never as the PO number. A file with an explicit PO / Source Document column is split by that column. Loading a PO that is already loaded starts a re-import preview.

    2 · UOM definitions

    Built-in: CTN<n> = n PCS (Odoo and physical), PCS = 1 (exact text only), Pack of <n> = n PCS (physical only). Anything else — bare CTN, Tray, 6X4, By 24, CTNP… — is UOM NEEDS REVIEW until an approved definition is added here. Approved definitions are kept in this browser across shipments (export them to move to another computer). A temporary conversion typed on a single row never becomes a definition by itself.

      5 · Bulk import (optional)

      Header names are detected (Product, Physical Barcode, Physical Qty, Expiry, Notes, Physical UOM, Pieces per pack, Weight/Spec, and an optional PO column). A PO value matching a loaded PO links the row to it; an unknown PO value sends the row to PO SELECTION REQUIRED. Without recognisable headers the v1 order is used. Safe to re-import a growing file; already-checked-in rows are skipped.

      7 · Session & export

      The session (POs, rows, decisions) autosaves to this browser under a v3 key — v1 and single-PO v2 sessions are never overwritten. Older session backups (.json) can be loaded and are migrated. Clearing the session keeps the approved UOM definitions.

      8 · Damaged items (0)

      All damaged items in this shipment appear here, regardless of the PO filter. Enter or edit damaged quantities in Check in an item. Rows with damage are excluded from Odoo uploads.

      #POProductPhysical UOMPhysical qtyDamaged qtyUsable qtyReview

      Receiving cases (per PO; quantities compared in the Odoo UOM, summed per PO line or identical-line group): 1 same barcode + same qty → READY (only if UOM and weight/spec agree) · 2 same barcode + different qty → QUANTITY MISMATCH · 3 different barcode + same qty → ADDITIONAL BARCODE if the PO barcode is formal, otherwise NEW PRODUCT / EXCHANGE BARCODE REVIEW · 4 different barcode + different qty → the same + QUANTITY DIFFERENCE REVIEW · 5 ordered, nothing received → MISSING · 6 received, not ordered → EXTRA / NOT ON PO.

      Formal barcode = exactly 13 numeric digits, evaluated on the PO / Odoo barcode.

      Multiple POs — a row belongs to exactly one PO. Product on several POs and no PO chosen → PO SELECTION REQUIRED; chosen PO lacks the product but another PO has it → PO MISMATCH — NEEDS REVIEW. Use Split row when one physical receipt covers several POs; the tool never allocates quantities by itself. Identical duplicate lines inside one PO (same barcode, internal ref, name, UOM, pieces, weight) are received as one group; their original lines stay listed.

      Odoo quantity = physical qty × pieces per physical unit ÷ pieces per Odoo unit (via PCS). Undefined UOMs → UOM CONVERSION — NEEDS REVIEW; the tool never guesses a conversion and never uses "* 10" from a product description.
